# 问题记录

## I-001｜LLM 请求延迟高并发生超时

- 日期：2026-08-25
- 现象：真实 LLM 对局中单次请求耗时从数秒到数十秒，部分请求超时。
- 影响：整局执行时间过长；没有容错时会直接中断对局。
- 原因：六名玩家按阶段串行调用模型，模型推理和网关延迟波动较大。
- 状态：`FIXED`（已增加有限重试和安全降级）；仍通过输出长度和请求参数继续优化。

## I-002｜模型行动名称与规则枚举不一致

- 日期：2026-08-25
- 现象：模型返回 `kill`、`speech`、`night_seer`、`no_action` 等名称，规则只接受 `wolf_kill`、`speak`、`inspect`、`noop`。
- 影响：行动被拒绝，狼人无法协同攻击，发言和查验缺失，规则合规评估失败。
- 原因：Prompt 没有按阶段明确枚举，Policy 也没有协议归一化和 Schema 校验。
- 状态：`FIXED`（已增加阶段协议、别名归一化和本地 Schema 校验）。

## I-003｜模型失败后的 `noop` 在部分阶段被拒绝

- 日期：2026-08-25
- 现象：请求超时后降级为 `noop`，但投票、发言等阶段原规则不接受 `noop`。
- 影响：安全降级仍产生 `action_rejected`，污染规则合规指标。
- 原因：降级策略与阶段规则没有统一协议。
- 状态：`FIXED`（规则引擎接受安全无动作，并保持阶段结算语义）。

## I-004｜真实 LLM 报告仍显示离线，费用为 0

- 日期：2026-08-25
- 现象：真实模型运行的报告包含 `offline: true`，模型费用固定为 `0.0`。
- 影响：运行模式和成本指标不可信。
- 原因：评测函数把 `offline` 写死，适配器没有读取模型价格配置。
- 状态：`FIXED`（报告接收运行模式，适配器按 Token 和价格配置计算费用）。

## I-005｜Prompt 改造初期缺少 `Phase` 导入

- 日期：2026-08-25
- 现象：新增阶段行动 Prompt 后，测试在构造 Prompt 时出现 `NameError: Phase is not defined`。
- 影响：LLM Policy 相关测试无法运行。
- 原因：`visibility.py` 使用了 `Phase`，但重构导入列表时遗漏。
- 状态：`FIXED`（补充导入并重新执行专属测试）。

## I-006｜安全 `noop` 的来源缺少可观测性

- 日期：2026-08-25
- 现象：最新运行规则拒绝为 0，但 14 次模型调用只产生 1 次发言和 1 次弃票；报告无法区分模型主动 `noop` 与格式/Schema 失败后的降级 `noop`。
- 影响：`rule_compliance: true` 不能代表 Agent 真的完成了有效决策，模型行为质量难以评估。
- 原因：已接受的 `noop` 不写入事件，`model_failures` 目前只统计 `llm_` 适配器失败，不单独统计 `invalid_model_output`、Schema 失败、主动 `noop` 和弃票。
- 状态：`FIXED`（增加脱敏请求级 JSONL 追踪和细分决策指标）。

## I-007｜输出 Token 上限导致大量 JSON 截断

- 日期：2026-08-25
- 现象：最新运行 32 次 HTTP 请求全部成功，但 20 次响应的 `output_tokens` 恰好为 512，并被判定为 `invalid_json`。
- 影响：62.5% 的模型决策降级为 `noop`，有效行动率只有 18.75%；狼人第二轮无法协同攻击，投票没有有效目标，最终平局。
- 原因：`max_tokens=512` 可能同时限制模型推理和最终 JSON；输出达到上限时，最终 JSON 未完整返回。
- 最新验证：提高上限后，本次 30 次请求中仍有 2 次 `invalid_json` 和 1 次 Schema 降级；有效行动率升至 66.7%，但总耗时升至 381967 ms，仍需在输出完整性与延迟之间调参。
- 最新处理：结构化行动默认关闭 thinking，默认输出上限调整为 2048；投票目标和弃票字段增加 Policy 层校验；格式或 Schema 失败最多追加一次修复请求。需要真实网关 smoke test 验证截断率和延迟是否改善。
- 最新验证（2026-08-25）：真实网关 Seed 7/18/23/31/42 共 136 次请求，`output_truncated=0`、预算升档 0 次、降级 0 次、规则拒绝 0 次；平均延迟 1295ms，P95 2227ms，最大 3344ms。两个 `.env` 未配置 Token 单价，因此报告成本仍为 0，实际美元成本待补充价格配置后重跑。
- 状态：`FIXED`（截断率和延迟已完成真实网关验证；成本指标仍待价格配置）。

## I-008｜Prompt 历史上下文逐轮膨胀

- 日期：2026-08-25
- 现象：最新运行输入 Token 从第 1 轮平均 909 增长到第 2 轮平均 2227，最大达到 2839；白天投票阶段平均 1958。
- 影响：每个 Agent 重复携带完整事件元数据和历史文本，增加输入成本、请求延迟和后续多轮游戏的上下文压力。
- 原因：Prompt 同时传入完整 `Event.to_dict()`、嵌套 JSON 字符串 `untrusted_public_transcript`、重复阶段/轮次元数据和无实际信息的固定 `private_memory`。
- 状态：`FIXED`（已完成无语义变化的 Prompt 压缩；后续仍可通过事件窗口和摘要继续优化多轮上下文）。
- 修复范围：事件仅保留轮次、阶段、类型和完整 payload；公开 transcript 直接传数组；固定无信息私有记忆不再传给模型。
- 边界：未引入摘要、未改变授权过滤、行动协议或游戏规则。

## I-009｜非关键 decision_label 类型错误导致合法行动降级

- 日期：2026-08-25
- 现象：最新运行 8 次白天讨论响应出现 `decision_label_type`，其中 6 次修复失败并降级为 `noop`。
- 影响：非关键辅助字段错误触发完整行动 Schema 失败，增加修复请求并减少有效发言。
- 原因：Policy 将 `decision_label` 当作严格字符串字段校验，但它不参与行动规则结算。
- 状态：`FIXED`（缺失、`null` 或非字符串统一规范为空字符串，字符串仍限制 80 字）。

## I-010｜规则需要隐藏投票并轮换发言顺序

- 日期：2026-08-25
- 现象：原实现投票提交后立即公开 `vote_cast`，且白天始终按固定玩家列表发言；无狼人袭击目标时，女巫还可提交 `witch_save(null)`。
- 影响：投票顺序会影响后续玩家决策，发言首位长期固定，女巫可能错误消耗解药。
- 原因：投票事件在 `submit_action` 阶段生成；发言调度没有轮次轮换；救药校验只比较目标相等，没有排除空袭击目标。
- 状态：`FIXED`（投票改为全员提交后一次性公开票型，发言按座位轮换，空袭击目标禁止解药）。

## I-011｜模型目标语义直到规则层才被拒绝

- 日期：2026-08-25
- 现象：Seed 18 的模型输出结构合法，但狼人选择已死亡玩家作为 `wolf_kill` 目标，直到 `rules.py` 才产生 `action_rejected / invalid_target`。
- 影响：模型协议错误污染规则拒绝指标，也增加了本可避免的非法 Action 进入环境边界的机会。
- 原因：`LLMPolicy` 原先只校验 JSON、阶段和投票目标，没有提前校验夜间角色行动的目标语义。
- 状态：`FIXED`（Policy 层已补充目标存活、自指、狼人队友和解药目标一致性校验；规则层继续保留最终防线）。

## I-012｜终端观战输出混入完整 JSON

- 日期：2026-08-25
- 现象：`--spectate` 已输出公开叙事，但程序结束时仍无条件打印完整 JSON，导致 stdout 包含私有事件类型和角色。
- 影响：终端观众可看到不应公开的上帝视角信息；观战隐私测试失败。
- 原因：CLI 的最终 payload 输出没有根据 `--spectate` 分支。
- 状态：`FIXED`（非 JSON 观战只输出公开叙事和页面路径；JSON 观战保持 stdout 合法 JSON）。
