# 第 16 课毕业项目：六 Agent 狼人杀技术方案

## 目标与范围

将第 15 课的社会模拟扩展为 `Werewolf Arena`：六名独立 Agent 在不完全信息环境中完成夜晚行动、白天讨论和投票。项目默认离线运行，规则引擎可重复回放；模型只作为可替换的 Policy，不能直接修改游戏状态。

本期固定为六人局：2 名狼人、1 名预言家、1 名女巫、2 名村民。默认不公开死亡玩家的身份。特殊角色、真实联网模型和图形界面不在离线核心的验收范围内，但模型适配接口必须为后续接入保留。

## 规则

### 胜负条件

- 所有狼人死亡：好人阵营胜利。
- 存活狼人数量大于或等于存活好人数量：狼人阵营胜利。
- 达到 `max_rounds` 仍未分出胜负：状态为 `DRAW`，用于控制离线成本和避免无限局。

### 夜晚

1. 两名存活狼人分别选择一名非狼人存活玩家；只有目标一致时，形成袭击目标，否则本晚袭击失败。
2. 存活预言家查验一名其他存活玩家，得到私有的 `werewolf` 或 `good` 结果。
3. 存活女巫看到袭击目标（或袭击失败），可选择保存该目标、毒杀一名其他存活玩家，或不行动。解药与毒药各只能使用一次，且同一夜最多使用一种药。
4. 环境结算死亡，不公开死亡角色；夜晚私有信息会被写成带收件人的事件。

### 白天

1. 环境公开宣布夜晚死亡名单。
2. 每名存活玩家按固定顺序发言一次；发言最多 240 字符，作为不可信数据写入公共事件。
3. 每名存活玩家投给另一名存活玩家；最多票者出局，最高票并列则无人出局。
4. 每次死亡后立即检查胜负。

## 信息与安全边界

`GameState` 仅属于引擎。`VisibilityProjector` 为每名玩家生成 `PlayerObservation`：

- 所有人可见：阶段、轮次、存活名单、公开事件、历史发言与投票。
- 自己可见：自己的身份、存活状态、私有记忆、个人资源。
- 狼人额外可见：仍存活的狼人队友与狼人私有协作事件。
- 预言家额外可见：自己的查验结果。
- 女巫额外可见：当晚袭击目标、自己的药物剩余量。

任何 `Policy` 只接收 `PlayerObservation`；不得将 `GameState` 或其他玩家的私有事件序列化进 Prompt。公共发言须标记为 `<untrusted_public_transcript>`，不得作为系统指令执行。凭证只从环境变量读取，状态和日志中不得写入 API key。

## 架构

```text
GameState (引擎上帝视角)
        |
        v
VisibilityProjector -> PlayerObservation -> Policy / LLMPolicy -> Action
        ^                                                        |
        |                                                        v
        +------------------- GameRules / GameEngine <--- Event --+
                                     |
                                     v
                       Checkpoint / JSONL trace / Evaluation
```

- `schemas.py`：角色、阶段、状态、行动、事件和 JSON Schema。
- `rules.py`：权威规则、合法性校验、夜晚结算、投票结算和胜负判断。
- `visibility.py`：信息投影和 Prompt 构造。
- `policies.py`：规则 NPC、脚本模型和模型策略协议。
- `engine.py`：阶段调度、事件记录、最大轮次、恢复。
- `storage.py`：原子 checkpoint、JSONL 轨迹和报告。
- `evaluation.py`：胜负、规则拒绝、隐私泄露、调用成本和延迟统计。

## LLM 策略接口

`ModelAdapter.complete(system_prompt, user_prompt) -> ModelResponse` 是唯一的模型边界。`LLMPolicy` 将 Observation 转为包含 JSON Schema 的 Prompt，再严格解析为 `Action`；解析错误、超时或非法行动会退回 `noop`，但仍由环境记录并校验。默认使用 `ScriptedModelAdapter`，不联网。

模型输出只允许：行动类型、目标、公开发言、简短决策标签。项目不要求或保存模型的完整思维链。

## 持久化、恢复与评测

- 每个阶段后可写入版本化 JSON checkpoint；恢复从下一阶段继续，保留原事件 ID。
- `events.jsonl` 保存完整事件轨迹；私有事件有收件人列表，展示层必须二次做授权过滤。
- 评测输出胜者、轮数、行动拒绝数、发言数、投票数、模型调用数、Token、成本、延迟、规则合规与隐私审计。
- 相同 seed、角色排列、Policy 和最大轮数必须得到相同结果；离线测试比较连续运行与 checkpoint 恢复结果。

## 验收

1. 固定 seed 产生 2 狼人、1 预言家、1 女巫、2 村民。
2. 村民 Observation 不能包含狼人队友、查验结果或女巫药物；狼人只能看到自己的队友。
3. 非法阶段行动、死亡玩家行动、非法目标与重复药物使用都被环境拒绝。
4. 能执行正常、袭击失败、女巫救人、平票、达到轮数上限等离线场景。
5. checkpoint 恢复与连续运行得到相同的状态和事件。
6. CLI 能输出 JSON、轨迹和评测报告；默认不访问网络。
