# 第十二课：RAG 可信回答、引用与拒答

## 1. 本课目标

上一课解决了“如何把更相关的片段找出来”，本课继续解决：

```text
检索到了内容，模型是否真的依据这些内容回答？
用户能否知道答案来自哪里？
资料不足时，模型是否会拒答？
```

本课会实现：

- 给每个检索片段分配稳定的证据编号，例如 `[R1-1]`；
- 在系统提示词中要求模型基于证据回答；
- 检索分数过低时返回“资料不足”；
- 检查最终答案是否使用了本轮检索结果中的引用；
- 通过评测脚本同时检查来源和证据编号。

## 3. 证据编号

工具返回的结果类似：

```text
[R1-1] 来源：memory.md#memory-2
证据内容：持久化记忆可以写入 JSON、SQLite 或数据库。
```

模型回答时应该写：

```text
持久化记忆可以写入 JSON 或数据库。[R1-1]
```

`R1-1` 的含义是：

- `R1`：第 1 轮证据检索；
- `1`：这轮检索返回的第 1 个片段。

这样引用不是模型随便编造的字符串，而是可以和本轮工具结果对应起来。

## 4. 资料不足

本课使用一个简单阈值：

```python
MIN_RELEVANCE_SCORE = 0.45
```

如果最高重排分数低于阈值，搜索工具会返回资料不足，并要求模型不要根据常识补充。

这个阈值只是学习用的启发式规则。真实项目需要用测试集调节阈值，并分别评估“应该回答”和“应该拒答”的问题。

## 5. 引用校验

程序使用正则表达式提取回答中的引用：

```python
re.findall(r"\[(R\d+-\d+)\]", answer)
```

然后比较两组集合：

```text
回答中的引用
      ↓
本轮检索实际提供的引用
      ↓
检查是否缺失或引用了不存在的编号
```

注意：当前校验器只能检查引用格式和编号是否存在，不能证明模型的每一句话都真正被证据支持。这是后续评测课程要继续解决的问题。
