## 三层实现标准

- 概念层：区分短期记忆、长期记忆、外部知识库、分块、召回、重排和引用。
- 最小实践层：用固定文档和关键词检索展示记忆读取、top-k 和来源返回。
- 工程实现层：实现可替换的 Memory/Retriever 接口，补充文件或数据库持久化、向量检索、租户隔离、删除策略、引用校验、缓存和检索评测；离线关键词检索继续保留。

当前工程实现已经补齐可替换接口、SQLite 记忆、离线向量/混合检索、租户隔离、删除策略、缓存、引用校验和评测；它仍然是教学级实现，不能直接等同于生产级向量数据库和完整记忆治理。

## 三种“记忆”

短期记忆是当前会话消息和工具观察，决定模型眼前能看到什么；长期记忆是跨会话保存的用户偏好、事实或经验；外部知识库是可更新的文档集合，通常通过 RAG 在请求时检索，而不是把所有内容永久塞进 prompt。三者的生命周期、权限和删除策略不同，不能混成一个列表。

```mermaid
flowchart LR
    Q[查询] --> W[查询改写]
    W --> R[关键词/向量检索]
    R --> F[过滤与重排]
    F --> C[上下文窗口]
    H[会话历史] --> C
    P[长期偏好] --> C
    C --> L[LLM]
```

RAG 的质量来自分块、召回、去重、重排、引用和回答约束的整体组合。记忆写入前应判断是否稳定、有用、允许保存；读取时应按用户和租户隔离。缓存不能替代事实来源，模型自称“internal knowledge”也不能当引用。

## 实践与验收

Demo 提供内存会话、固定知识和关键词检索。工程实现进一步提供：

- `ShortTermMemory`：当前进程会话消息；
- `SQLiteMemoryStore`：带 `tenant_id`、`user_id` 的长期记忆；
- `KeywordRetriever`、`VectorRetriever`、`HybridRetriever`：统一检索接口；
- `RetrievalCache`：索引版本改变时自动避免旧结果命中；
- `build_evidence()` 和 `validate_citations()`：来源编号及引用校验；
- `evaluate_retriever()`：离线检索指标；
- `answer_with_llm()`：证据不足时在模型调用之前拒答。

验收：能解释检索结果如何进入上下文，以及为什么记忆写入、读取、删除都需要独立策略；能用测试验证不同租户无法读取或删除彼此的记忆。
