# Werewolf Arena 产品成熟度清单

更新日期：2026-08-25。项目当前是“可重复运行、可审计的离线六 Agent 游戏内核”，不是已经面向用户发布的完整游戏产品。

标记说明：`[x]` 已实现并有离线验证；`[~]` 已有接口或骨架，但未做真实线上验证；`[ ]` 尚未实现。

## 已实现：游戏内核

- [x] 固定六人局：2 狼人、1 预言家、1 女巫、2 村民。
- [x] 确定性身份分配：相同 seed 能得到相同开局并支持回放。
- [x] 完整阶段状态机：狼人私密协商 → 狼人确认投票 → 预言家查验 → 女巫行动 → 白天发言 → 投票 → 胜负检查。
- [x] 狼人只有在两人选择相同目标时才完成袭击。
- [x] 狼人先私密协商候选目标，再独立确认；个人确认票在狼人阶段内隐藏。
- [x] 预言家查验结果仅本人可见。
- [x] 女巫拥有一次解药和一次毒药，同一晚最多使用一种药；没有狼人袭击目标时不能使用解药。
- [x] 白天按轮换首发顺序发言；投票期间隐藏个人票型，全部提交后公开个人票型和总票数，平票无人出局。
- [x] 默认不公开死亡玩家身份。
- [x] 狼人全部出局时好人胜；存活狼人不少于好人时狼人胜；到达轮数上限判平局。
- [x] 非法阶段、死亡玩家、错误身份、非法目标、重复行动和药物耗尽都会被环境拒绝。

## 已实现：Agent 与信息边界

- [x] 引擎保留完整 `GameState`，玩家只能获取自己的 `PlayerObservation`。
- [x] 村民看不到狼人队友、预言家查验和女巫药物。
- [x] 狼人只能看到仍存活的狼人队友。
- [x] 预言家只能看到自己的查验结果；女巫仅在自己的夜晚看到袭击目标。
- [x] 公共发言被作为不可信游戏数据传入模型 Prompt。
- [x] Action 和 Event 分离：Agent 只提出行动，规则引擎才改变状态。
- [x] 默认 `RulePolicy` 可在不调用 LLM 的情况下完整运行游戏。
- [x] `ScriptedModelAdapter` 可用于离线测试模型输出和失败分支。
- [~] `LLMPolicy` 与 OpenAI Chat Completions 兼容适配器已实现阶段行动协议、常见别名归一化、本地 Schema 与目标语义校验、默认关闭 thinking、一次格式修复重试、有限重试、失败 `noop` 降级、输出上限、Token 价格和非敏感进度事件；真实端点仍需多局 smoke test 验证输出截断率、延迟和 Seed 18 修复效果。

## 已实现：可运维性与质量基础

- [x] 每个阶段后可保存版本化 JSON checkpoint。
- [x] 中断恢复不会重复已完成阶段的事件。
- [x] 保存 `events.jsonl` 事件轨迹和 `report.json` 评测报告。
- [x] 原子写入 checkpoint 和报告，降低中断导致半个文件的风险。
- [x] 输出胜负、轮数、拒绝行动、发言、投票、调用次数、Token、成本、延迟和请求级决策指标。
- [x] 基础公开事件隐私审计。
- [x] 专项自动化测试覆盖角色、可见性、夜晚、投票、发言顺序、模型目标语义、模型降级、请求观测、恢复、CLI、公开叙事和评测。

## 达到“稍微成熟、可玩的 Agent 游戏”前必须补齐

### 游戏体验与玩法

- [x] 狼人私聊协商阶段：两名狼人先各发一条私密建议，再进入独立确认投票；分票或弃票不形成袭击。
- [ ] 更真实的讨论回合：当前每位玩家每天只发言一次，首发顺序已按座位轮换；仍需支持多轮讨论、追问、回应和发言时间/字数预算。
- [ ] 可配置规则：死亡是否翻牌、女巫是否可自救、狼人意见不一致如何处理、平票后是否加赛、角色组合等。
- [x] 玩家可读的游戏叙事：将公开 Event 转成夜晚结果、发言、票型和出局公告。
- [~] 旁观者/裁判视图与玩家视图分离：已有只读静态观战页，完整权限系统仍待 Web 服务化。
- [ ] 可复现的预设局面：方便演示“预言家验狼”“女巫救人”“狼人翻盘”等场景。

### LLM 游戏能力

- [ ] 至少用一个真实模型完成多局端到端 smoke test，并记录实际成本、延迟和失败率。
- [ ] 为不同身份提供更专业的 Prompt：狼人协作/伪装、预言家信息披露、女巫资源管理、村民证据推理。
- [ ] 动态长期记忆：当前只保存初始私有记忆和私有事件；需要按轮总结“已知事实、怀疑、承诺、查验、票型”。
- [ ] 上下文预算与摘要：多轮发言会快速撑满上下文，必须限定窗口、压缩旧记录并保留关键证据。
- [x] 严格 JSON Schema 校验：当前在本地校验字段、类型、长度、阶段枚举和投票目标；格式错误最多触发一次修复请求，仍失败则安全降级。
- [x] 模型超时、限流、HTTP 失败和供应商返回异常的安全降级。
- [ ] 每位 Agent 独立模型配置、温度、Token 预算和 Prompt 版本，支持实验比较。

### 产品界面与交互

- [x] 本地终端 `--spectate` 和自包含 `spectator.html` 剧场回放；公开时间线显示轮次、阶段、发言和投票结果。
- [x] 显式 `--god-view` 生成独立的完整状态审计页，展示身份、私有事件和规则诊断；普通观众页继续隔离敏感数据。
- [ ] Web 服务 API：创建房间、开始游戏、查询状态、提交/流式获取事件、恢复游戏。
- [ ] 实时界面：玩家列表、日夜切换、聊天区、投票面板、身份私密卡片和结果页。
- [ ] WebSocket 或 SSE：向前端实时推送发言、投票和阶段变化。
- [ ] 人类玩家模式：让人类占据一个角色，与其余 Agent 同局游戏。
- [ ] 房间、观战、历史战报和可分享回放。
- [~] 回放界面必须按观众权限过滤私有事件，不能直接读取完整 JSONL：静态 `spectator.html` 已隔离；上帝视角仅供开发/裁判使用，正式服务权限仍待 Web 化。

### 安全、隐私和公平

- [ ] 服务端认证、房间授权和角色会话令牌；当前只是本地文件模拟，不存在真实用户权限。
- [ ] 将 checkpoint、完整事件轨迹放入受保护存储；它们包含真实身份和私有事件，不能作为公开下载文件。
- [ ] 日志脱敏、数据保留期限和玩家删除机制。
- [ ] 更全面的 Prompt 注入防护：发言文本隔离已经存在，但还需检测、审计和异常策略。
- [ ] 内容安全策略：限制辱骂、骚扰、现实伤害威胁和模型不当输出。
- [ ] 服务端限流、成本上限、单局 Token 上限和异常终止机制。
- [ ] 防作弊与公平性：禁止客户端伪造 Action，所有身份和结算必须仅在服务端保存与验证。

### 可靠性与运营

- [ ] 数据库替代本地 JSON 文件，至少支持多房间并发、索引查询和可靠恢复。
- [ ] 任务队列或 Actor 调度器，确保同一游戏的阶段串行、不同游戏可并行。
- [~] 模型调用已有超时、退避和有限重试；尚未实现熔断与备用模型策略。
- [~] LLM 请求已有脱敏结构化 JSONL、请求 ID 和决策追踪；监控仪表盘、告警和跨运行聚合尚未实现。
- [ ] 部署配置：容器化、环境变量样例、健康检查、迁移和备份策略。
- [ ] 压力测试：并发房间数、单局时延、模型调用失败和恢复演练。

### 游戏质量与评测

- [ ] 多局锦标赛：按角色、模型、Prompt、温度和 seed 统计胜率。
- [ ] 狼人协作质量、预言家查验命中、村民投票命中、女巫药物价值等专项指标。
- [ ] LLM 发言质量评测：相关性、逻辑一致性、身份泄露、重复率和攻击性。
- [ ] Prompt/模型版本回归门禁：新版本不能让胜率、延迟、成本或隐私指标显著恶化。
- [ ] Elo 或其他对局强度评分，避免仅用单局输赢判断模型能力。

## 建议实施优先级

### P0：先做到“能看、能玩、可控”

1. 多轮白天讨论和回应。
2. 一个真实模型的单局 smoke test、超时处理和成本上限。
3. 完整 Web 观战/玩家界面（当前已有静态观战草图）。
4. 规则配置和预设局面。
5. 完整事件、checkpoint 的服务端权限边界。

### P1：再做到“能稳定试玩”

1. 房间 API、WebSocket/SSE、基础前端。
2. 数据库、并发调度、错误重试和观测。
3. Prompt 注入/内容安全、限流和审计。
4. 人类玩家加入一局游戏。

### P2：最后做到“可比较、可迭代”

1. 多局锦标赛和可视化回放。
2. 模型、Prompt、温度和角色配置实验。
3. 自动化评测门禁、Elo 和成本优化。

## 当前推荐定位

当前版本最适合定位为：

> 一个用于研究和验证多 Agent 不完全信息博弈的离线狼人杀引擎。

完成 P0 后可定位为：

> 一个可供少量用户观战和试玩的 LLM 多 Agent 狼人杀 Demo。

完成 P1 和 P2 后，才适合定位为可持续运行、可比较模型策略的游戏产品。
