# 第七课：文档切分、Top-K 与来源引用

## 1. 为什么需要切分

如果整篇文档作为一个检索单位，文档中只有一小段相关内容时，模型仍会收到整篇文档。文档变多后，会浪费上下文空间。

本课按空行切分段落，每个片段都有：

```text
source：来源文件
chunk_id：片段编号
text：片段内容
```

## 2. Top-K

`top_k` 表示最多返回多少个相关片段。本课把它限制在 1 到 5 之间，并默认返回 3 个。

K 太小可能漏掉答案，K 太大可能把无关内容也放进上下文。

## 3. 来源引用

检索结果包含：

```text
来源：tool-calling.md#tool-calling-2
相关度：0.42
```

模型可以据此在最终答案中标记引用。注意：引用格式只是本课的学习约定，生产系统还需要验证引用是否真的支持答案。

## 4. 练习

1. 把 `DEFAULT_TOP_K` 从 3 改成 1，观察答案变化；
2. 在 `knowledge` 中增加一个 Markdown 文件，重新运行程序；
3. 把一个段落拆成更短的两个段落；
4. 观察 `本轮工具调用数量`，解释模型为什么调用一次或多次搜索。
