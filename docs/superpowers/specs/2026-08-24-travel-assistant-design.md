# 第 13 课智能旅行助手工程设计

## 目标

构建一个离线、可审计的旅行 Agent 工程骨架，把需求结构化、外部工具查询、候选行程规划、约束校验、人工审批和幂等预订明确分层。

## 范围

默认使用固定航班、酒店和天气 Provider，不调用真实支付或预订 API。实现接口可被真实服务替换，并覆盖时区、币种、库存有效期、天气失败降级、隐私脱敏、审批和重复请求处理。

## 架构

`schemas.py` 定义旅行请求、候选资源、行程和预订状态；`normalization.py` 校验日期、时区和币种并脱敏隐私；`providers.py` 定义可替换工具协议和离线 Fixture；`planner.py` 只生成行程草案，不产生外部副作用；`booking.py` 负责审批状态机和幂等；`storage.py` 保存计划、审计和预订产物；`experiment.py` 编排 Demo。

核心安全边界是：搜索和规划可以自动运行，预订和付款只能在明确审批后执行。所有外部结果必须带来源、抓取时间和过期时间；过期库存不能进入可预订候选。

## 数据与约束

- 支持出发地、目的地、日期、同行人数、预算、币种、天气偏好和隐私字段。
- 统一使用带时区的 ISO 时间；金额统一转换为 CNY 进行比较，再按请求币种展示。
- 预算、日期、库存、目的地匹配和天气偏好是可测试的硬约束。
- 天气工具失败时保留行程候选，但必须产生降级警告。
- 护照号、电话等字段只能脱敏进入日志和报告。
- 相同幂等键的预订请求只能产生一个 reservation。

## 验收标准

1. 能从结构化需求生成预算内的两日候选行程。
2. 能过滤日期不匹配、预算超限和过期库存。
3. 天气工具失败时能降级并记录警告。
4. 未审批的预订只能进入 `PENDING_APPROVAL`。
5. 审批后可确认预订，重复幂等请求返回同一 reservation。
6. 报告中不暴露护照号和联系方式。
7. 专属测试覆盖约束、Provider 失败、隐私、审批和幂等恢复。
